# 编码规范

## 1. Git 提交规则

采用 Conventional Commits，格式：`<type>(<scope>): <中文描述>`（现有提交即此格式）。

| type | 用途 |
|------|------|
| `feat` | 新功能 |
| `fix` | 修复缺陷 |
| `refactor` | 重构（不改行为） |
| `perf` | 性能优化 |
| `test` | 测试 |
| `docs` | 文档 |
| `style` | 格式 / 换行（不改逻辑） |
| `chore` | 构建、依赖、配置 |

约定：
- 描述用中文，一句话说清「为什么」，控制在 50 字内；
- 单次提交只做一件事，不把多个无关改动混在一次提交；
- 不提交密钥 / 证书 / 大体积二进制（见 `.gitignore`）；
- 不主动 commit（见 `AGENTS.md`）；不装 commit-msg hook 强制校验，靠自觉遵守。

## 2. 代码风格

- `dart format`（默认行宽 80），提交前必跑；`flutter analyze` 必须零 issue；
- `analysis_options.yaml` 目前是 `flutter_lints` 默认模板，新增 lint 需在该文件显式声明，
  不要在业务代码里滥用 `// ignore:`；
- 命名：文件 / 目录 `snake_case`；类 `UpperCamelCase`；变量 / 方法 / 常量 `lowerCamelCase`；
- 导入：`dart:` → `package:` → 包内相对导入，组间空行（见 `lib/main.dart`）；
- 注释统一**中文**，公开 API 用 `///` 文档注释；术语（CDP、HLS、MSE、isolate、chunk）保留原文。

## 3. 日志

- 统一走 `lib/core/logging/app_log.dart`：全局
  `logDebug / logInfo / logWarn / logError(tag, message)`，或 `AppLog.instance.*`。
  业务代码**禁止 `print`**（`avoid_print` 已开启）；唯一例外是 `app_log.dart` 内部的
  debug 输出，且带 `// ignore: avoid_print`；
- `tag` 用模块名（`Boot` / `WebView` / `CdpSniffer` / `Download` / `FFmpeg` / `Transcode`），
  `message` 带关键上下文（域名、文件名、字节数、耗时），不打完整文件内容或大对象；
- 关键回调有没有触发，用 `AppLog.instance.bump('域.事件')` 记计数
  （如 `cdp.responseReceived`、`sniffer.shouldIntercept`、`sniffer.captured`），
  诊断页靠这些计数器判断嗅探为什么没结果；
- 日志只写本地文件（下载目录 `SniffingBrowser/logs/app.log`）与内存，
  **不接远程日志上报**；`warn` / `error` 在生产环境也要留，`debug` / `info` 只用于排查；
- 排错靠「设置 → 排查 → 运行日志」：搜索框按关键字过滤，或导出 txt
  （`logs/log-<时间戳>.txt`，合并磁盘历史，只留 3 份）。新增的日志要能被搜索到，
  所以把域名 / 文件名 / 状态码写进 `message`，别只写「失败了」；
- 导出后一律进应用内预览（`log_view_page`），不要直接弹系统分享面板——
  分享面板只负责把文件送出去，看不到内容，而排错第一步是「看一眼」。

## 4. 错误处理

- 全局捕获已装好：`runZonedGuarded` + `FlutterError.onError` +
  `PlatformDispatcher.onError`（见 `lib/main.dart`），不要重复装或绕过；
- 捕获异常时同时记录 `error` 与 `stackTrace`（如 `logError('X', '$e\n$s')`），
  禁止 `catch (e) {}` 静默吞异常；确实要忽略时写明原因；
- 面向用户的提示用中文短句，说明「发生了什么 + 怎么办」，不抛堆栈。
  例：无声视频抽 MP3 抛 `TranscodeUnsupportedSource` 并给出中文结论；
- 平台能力差异在 `core/platform/` 一层判定（`PlatformInfo`、`MediaExporter`），
  不在功能层散落 `try/catch` 兜底；
- Android 原生通道回复统一用 `{status, message?, uri?}` 结构，Dart 侧集中映射成
  `ExportResult` / 异常，不要把原生英文错误直接抛给用户；
- `startTranscode` 的 MethodChannel 回复必须挂到会话结束才返回，进度走同通道
  反向 `onProgress`；不要在 Dart 侧用轮询猜完成；
- 下载 / 合并失败要保留已落地的中间文件供重试与排查，不要静默删源文件；
- 原生崩溃（Windows `crash_*.dmp`）Dart 侧捕获不到，排查方式见 `README.md`。
