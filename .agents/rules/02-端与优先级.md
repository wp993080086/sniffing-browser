# 端与优先级

目标端只有三个：Windows、Android、HarmonyOS NEXT。
Web 与微信小程序**不在本项目范围内**——`lib/core/platform/platform_info.dart` 里
仅为 Web 预留了 `dart:io` 可用性判断，不代表要支持 Web 端。

| 端 | 状态 | 说明 |
|---|---|---|
| Windows | 首发基线，已端到端实测 | 嗅探走 CDP；转码调本机 ffmpeg；导出退化成纯 Dart 文件复制 |
| Android | **USB 真机在跑**，A2 已通过（85 / 83） | 嗅探走 `onLoadResource` + `shouldInterceptRequest`；MediaStore 导出与原生 FFmpegKit 转码已实现，转换成功自动入库，待 B 组真机用例验证 |
| HarmonyOS NEXT | 代码已写，未真机验证 | 需 Flutter-OH SDK 与 DevEco Studio，`ohos/` 目录尚未创建；原生导出 / 转码入口保持隐藏 |

## 文件落点

Android 只能直接写应用私有目录 `Android/data/<包名>/files/SniffingBrowser/`，
而 Android 11+ 的文件管理器进不去 `Android/data`，媒体库也不扫描那里。
所以**移动端任何用户可见的产物（下载、转换）都要再写一份进 MediaStore**，
否则「已完成」等于用户找不到文件。桌面端产物直接落用户下载目录，不需要这一步。

这条约束的由来见 `.agents/logs/changes/20261112/transcode-library-export.md`：
转 MP3 曾在真机上「转换完成」但音乐 App 里查无此文件。

**状态记录不要写进缓存目录。** 任务记录（`download_tasks.json` /
`transcode_jobs.json`）一律放 `StoragePaths.root` 这个私有 files 目录：
Android 的 `cache` 会在存储紧张时被系统静默清掉，用户也能在设置里一键
「清除缓存」，写在那里等于没持久化。

## 优先级

1. 先保证 Windows 链路不回退（唯一经过端到端实测的端）
2. Android USB 真机：跑 B1~B11，验证导出、三类转码、重启恢复
3. 鸿蒙：Flutter-OH SDK 与 `ohos/` 工程，暂缓

新增或修改公共能力时必须三端都能编译，不能只按当前开发端写死。

平台差异统一走 `PlatformInfo`（`lib/core/platform/platform_info.dart`），
不要在功能代码里直接写 `Platform.isAndroid` / `Platform.isWindows`。
`Platform.isOhos` 只存在于 Flutter-OH SDK，禁止直接使用。
