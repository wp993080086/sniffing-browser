# 版本策略

## 版本

| 组件 | 版本 / 约束 |
|---|---|
| Dart SDK（`pubspec.yaml`） | `>=3.9.0 <4.0.0`，同时容纳 3.35 与 3.44 两条版本线 |
| 官方 Flutter（日常开发 / Windows） | 3.44.9（本机已装） |
| Flutter-OH（鸿蒙构建） | 3.35.8-ohos，需配合 DevEco Studio 与 Flutter-OH SDK |
| `flutter_inappwebview` | `^6.1.5`；鸿蒙构建换成 CPF-Flutter 的 `br_v6.1.5_ohos` 分支 |
| `flutter_inappwebview_windows` | `^0.6.0`，Windows 必须显式引入，否则 `InAppWebView` 抛 `UnimplementedError` |

切鸿蒙时按 `pubspec.yaml` 末尾注释替换 WebView 依赖，再执行
`flutter clean && flutter pub get`。该 fork 保留 `android/` 与 `windows/` 目录，
一份依赖覆盖三端，不需要按平台拆依赖。

平台判定统一走 `PlatformInfo.current`（内部按 `Platform.operatingSystem` 分支判断
`'ohos'`），见 `lib/core/platform/platform_info.dart`。

## 架构铁律

下面几条都是实测踩坑结论，不要回退：

- **Windows 嗅探只能用 CDP 事件**（`Network.responseReceived` / `requestWillBeSent`）。
  `flutter_inappwebview_windows` 原生侧没有 `onLoadResource`；`shouldInterceptRequest`
  会对每个请求 `GetDeferral()` 挂起等 Dart 回话，一个首页两三百个请求就能把页面卡死。
  实现见 `lib/features/sniffer/data/cdp_sniffer.dart`。
- **`onPermissionRequest` 必须永远返回有效的 `PermissionResponse`（本项目一律 DENY）**。
  插件 0.6.0 的原生解码函数缺 null 检查，返回 null 会让进程 `0xc0000005` 闪退，
  且 Dart 侧的错误捕获看不到。规避见 `lib/features/browser/presentation/webview_host.dart`。
- **桌面转码调本机 ffmpeg 进程，不引预编译包**。Android 侧（2026-11-12 起）在
  `android/app/build.gradle.kts` 引 `dev.ffmpegkit-maintained:ffmpeg-kit-full:8.1.9`
  （LGPL AAR），由 `TranscodeBridge.kt` 实现已有的 `sniffing_browser/transcoder`
  MethodChannel；**不要引入 FFmpeg 的 Flutter pub 包**（会污染桌面与鸿蒙构建）。
  鸿蒙仍未接入。AAR 只含 arm64-v8a / x86_64，32 位 ABI 必须剔掉 —— 用
  `packaging { jniLibs { excludes += "lib/armeabi-v7a/**" } }`，
  **不要用 `defaultConfig.ndk.abiFilters`**：`flutter build apk` 会把
  `-Ptarget-platform` 透传过去覆盖它，看着写了其实不生效（2026-11-20 实证）。
- **下载先写 `.part` 临时文件再 rename，HLS 合并用流式写入**，
  中断不污染目标文件，也不把大文件整体读进内存。

桌面 FFmpeg 查找顺序：`SNIFF_FFMPEG_DIR` → exe 同目录（含 `bin/`、`ffmpeg/bin/`）
→ `~/.devtools/ffmpeg/bin/` → PATH；`ffmpeg` 与 `ffprobe` 都需要。
