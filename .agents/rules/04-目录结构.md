# 目录结构

以下以实际代码为准；`docs/tech-design.md` 第 7 章已同步为同一份实际目录。

```
lib/
├── main.dart                  # 入口：runZonedGuarded、AppLog.install、StoragePaths.init
├── app/                       # app.dart、providers.dart（SniffingBrowserApp 与全局 Provider）
├── core/
│   ├── constants/             # app_constants.dart
│   ├── logging/               # app_log.dart（AppLog、logXxx、bump 计数器）
│   ├── platform/              # platform_info.dart、storage_paths.dart、media_exporter.dart
│   └── utils/                 # hash_util.dart、format_util.dart
└── features/
    ├── browser/               # presentation: browser_page / browser_header / address_bar /
    │                          #               webview_host / home_page / tab_switcher /
    │                          #               history_page / bookmark_page / empty_hint
    │                          # providers: browser_provider（单页签状态）/
    │                          #            browser_tab / tab_manager（多页签）
    │                          # domain: history_entry / bookmark_entry
    │                          # data: history_store / history_service /
    │                          #       bookmark_store / bookmark_service
    ├── sniffer/               # domain: media_item / media_type / media_classifier
    │                          # data: sniffer_service / cdp_sniffer
    │                          # presentation: resource_panel / resource_tile /
    │                          #               sniff_fab（右下角悬浮入口）/ fab_position
    ├── downloader/            # domain: download_task / download_status / dash_pair
    │                          # data: download_queue / download_store（落盘）
    │                          #      / file_downloader / media_validator / hls/*
    │                          # presentation: download_page / download_tile
    ├── transcoder/            # domain: transcode_job
    │                          # data: transcode_queue / transcode_engine（含 NativeTranscodeEngine）
    │                          #      / system_ffmpeg_engine / transcode_store（落盘）
    │                          # presentation: transcode_page（进度与任务列表）
    ├── resolver/              # 站内视频解析（不走嗅探器）
    │                          # domain: resolved_video
    │                          # data: douyin_hook（JS 注入脚本 + 链接识别）
    │                          # presentation: video_resolver_page（入口在起始页）
    └── diagnostics/           # presentation: diagnostics_page（日志与通道计数器）

android/app/src/main/kotlin/com/sniffing/sniffing_browser/
├── MainActivity.kt            # 注册 media_exporter / transcoder 两个 MethodChannel
├── MediaExporterHandler.kt    # MediaStore 导出
└── TranscodeBridge.kt         # FFmpegKit 转码、进度、取消

tools/verify_download.dart     # 下载链路端到端验证脚本（12 项）
test/                          # 单元测试 + 需 RUN_E2E=1 开启的端到端测试
                               # native_transcode_engine_test.dart 覆盖原生转码协议
                               # transcode_library_export_test.dart 覆盖产物入库
                               # transcode_store_test.dart 覆盖落盘与重启恢复
docs/tech-design.md            # 技术方案（实现同步版）
```

分层约定：`features/<模块>/` 按 `domain` / `data` / `presentation` 划分（仅 browser 另有
`providers/`）；四个应用级单例集中在 `lib/app/providers.dart`，不要下放到页面里。
平台相关能力只放 `core/platform/`，功能层不直接碰原生通道。

界面职责：**发起**操作的入口可以挂在列表项菜单上，**进度与任务列表**必须有独立页面
（转换＝`transcoder/presentation/transcode_page.dart`）。原因：任务一旦只挂在下游记录上，
那条记录被移除/清空后用户就再也看不到它，真机上已经踩过这个坑
（见 `.agents/logs/changes/20261112/transcode-page.md`）。
