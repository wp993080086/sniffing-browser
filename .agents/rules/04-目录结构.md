# 目录结构

目录树可能滞后；本文件与实际目录不一致时，以实际目录为准并更新本文件。

分层约定：`features/<模块>/` 按 `domain` / `data` / `presentation` 划分（仅 browser 另有
`providers/`）；应用级单例集中在 `lib/app/providers.dart`，不要下放到页面里。
平台相关能力只放 `core/platform/`，功能层不直接碰原生通道。

已登记的当前取舍（2026-11-23 审查确认，不是规范豁免）：
- `system_ffmpeg_engine.dart` 里有 `Platform.isWindows` 与 `Process.start`：桌面 ffmpeg
  查找只服务转码一个 feature，下沉 core 收益有限；新增平台分支时再决定是否搬。
- `DownloadQueue` 同时承担调度、通知栏推送、DASH 合并编排：这些方法都需要任务的
  实时状态，拆成独立服务会引入一层回调；当前体量下保持单点，后续任务数增长再拆。
- `StorageManager` 放在 settings 下：它只服务设置页的存储管理入口，虽跨 downloader /
  transcoder 读状态，但不反向被二者依赖，不构成循环。

界面职责：**发起**操作的入口可以挂在列表项菜单上，**进度与任务列表**必须有独立页面
（转换＝`transcoder/presentation/transcode_page.dart`）。原因：任务一旦只挂在下游记录上，
那条记录被移除/清空后用户就再也看不到它，真机上已经踩过这个坑
（见 `.agents/logs/changes/20261112/transcode-page.md`）。
