# 计划：设置页日志入口 + 导出 txt

## 背景

现有 `DiagnosticsPage` 挂在浏览器顶栏，只能"复制到剪贴板"：

- 内存只有 800 条，重启即丢；真正要排的场景（闪退、白屏后重开）内存已经空了，
  而磁盘上的 `logs/app.log`（含 `app.log.1`）还留着现场，导出的却是内存。
- 没有搜索、没有级别过滤，800 条里找一行 403 得靠肉眼翻。
- 设置页没有入口，用户不知道有这个页面。

## 方案

1. `AppLog`
   - 待写队列改存 `LogEntry`，flush 成功后记 `_flushedUntil`，导出时据此只补
     没落盘的尾巴，不重复。
   - `exportBundle()`：`flushNow()` → 读 `app.log.1` + `app.log`（按字节读、
     malformed 容忍）→ 拼上内存尾巴，头部写版本 / 平台 / 存储根目录 / 日志路径 /
     计数器。
   - `banner()`：启动时写一条分隔线，多会话的日志一眼能看出分段。
2. `LogExporter`（新文件）
   - 写 `logs/log-YYYYMMDD-HHmmss.txt`，只保留最近 3 份，避免日志目录无限长。
3. 日志页
   - 关键字搜索（tag + 正文，大小写不敏感）、级别过滤（全部 / 警告以上 / 仅错误）、
     跨天时补日期。
   - 导出：移动端走系统分享（可存到文件、发出去）；桌面端落盘后用默认程序打开。
4. 设置页
   - 新增「排查」分区 → 运行日志；顺手把重复的「网络」分区标题改成「代理」。

## 不做

- 不做日志上传/云同步：单一用户、离线场景，导出文件足够。
- 不做按 tag 的 chips 过滤：搜索框能覆盖，标签行会长到一屏。

## 结果

全部按方案落地，唯一调整：设置页原来有两个同名「网络」分区标题，顺手把最后一个
改成「代理」。`flutter analyze` 零 issue，新增 16 个用例，全量 298 通过 / 9 跳过。
真机未验证的部分：移动端分享面板、桌面端 txt 打开方式。
